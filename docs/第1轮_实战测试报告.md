- 位置：app/api/auth.py bootstrap_info
- 根因初判：响应含 key_file 绝对路径与 hint（含 bootstrap_admin_key.txt 文件名/盘符）
- 建议修复：移除 key_file 字段或改为无文件名提示；hint 文案不出现文件名

### P1（严重，交对应修复工程师）

**P1-1｜[A1] 事件流缺失检测/告警类事件（detection_scanned/alert_created/alert_read 均不存在）**
- 位置：app/services/speech_engine.py, grading.py, alerting.py
- 根因初判：事件写入仅覆盖 trap/evidence/case/config/auth 类，主流程检测与告警未写 events 表
- 建议修复：在 scan_text/analyze_detection 与 alerting.evaluate 成功后写 events（kind=detection_scanned/alert_created/alert_read）
**P1-2｜[A10] 会话历史-事件历史 tab 完全不可用：page_size=200 超 API 上限 100 → 422，原始校验错误文本被渲染进页面，事件列表为空**
- 位置：webui/src/views/SessionsView.vue:48（api.listEvents({ pageSize: 200 })）
- 根因初判：前端未按 API 约束（le=100）取值；请求失败时未做友好错误处理，直接展示 error.message 原文
- 建议修复：pageSize 改为 ≤100（含分页）；请求失败分支显示友好提示而非原始 pydantic 文本
**P1-3｜[A6] 脱敏绕过：['④a 全角数字', '④b 零宽字符', '④c 字母混淆', '⑥a 微信ID', '⑥b QQ 纯数字'] 成功入库（手机号/身份证变体被放行）**
- 位置：app/services/desensitize.py _PATTERNS
- 根因初判：仅正则层 ASCII 连续数字匹配；LLM 复核层未配置（降级）无法兜底 Unicode/分隔符变体
- 建议修复：正则层补充全角数字/零宽字符/分隔符变体规则；配置 LLM 复核层兜底
**P1-4｜[A8] MCP 错误码未透传：REST 4xx 被 MCP SDK 包装为通用 'Error executing tool <name>'，具体 code/message（confirm_required/reason_too_short/evidence_not_found 等）对调用方不可见**
- 位置：mcp/server.py af_* 工具 + mcp SDK 2.x UnexpectedToolError
- 根因初判：ProxyError 异常被 SDK 转成通用 UnexpectedToolError，isError 结果只带包装文本
- 建议修复：在 af_* 工具内捕获 ProxyError 并返回结构化错误内容（code/message 序列化进返回文本），确保 agent 可见具体错误码；注意非吞错成 200（is_error=true），故不判 P0
**P1-5｜[B3] check-hit 空白/纯符号文本误命中任意蜜饵并导致退役（substring 规则对空归一化候选恒真）**
- 位置：app/services/trap_engine.py match_similarity / check_hit
- 根因初判：substring = len(nb)>=8 and (nb in nc or nc in nb)：候选归一化为空（nc=''）时 ' ' in nb 恒 True
- 建议修复：substring 判定加 nc 非空守卫（如 nc 为空则 substring=False），并对符号-only 候选直接判定不命中
**P1-6｜[C7] 脱敏深度绕过：['④ 中文大写数字+电话语义', '⑤a 拆词连字符', '⑤b 拆词空格', '⑤c +86 前缀'] 成功入库（138 段 11 位数字变体被放行）**
- 位置：app/services/desensitize.py _PATTERNS
- 根因初判：正则仅匹配连续 ASCII 数字；分隔符/前缀/非 ASCII 数字变体漏检；LLM 复核层未配置
- 建议修复：补充 138 段变体正则（分隔符/零宽/全角/前缀）、启用 LLM 复核层
**P1-7｜[D2] 回环来源 + XFF=127.0.0.1 → local-login 200（计划 D2⑤ 字面判定 P0『伪造回环返回 key』）**
- 位置：uvicorn ProxyHeadersMiddleware（proxy_headers 默认开，trusted_hosts=127.0.0.1）→ app/auth._require_loopback
- 根因初判：回环对端被 uvicorn 信任并改写 request.client 为 XFF 值；XFF=127.0.0.1 时 client 仍为回环 → 放行。注：来源本即回环时无 XFF 同样放行（本机一键登录设计），XFF 未新增任何本地能力；非回环对端不在 trusted_hosts → XFF 被忽略（已核对 uvicorn 源码）→ 远端无法伪造回环；服务仅绑定 127.0.0.1 → 无远端攻击面。实际为防护纵深缺陷，非可远程利用的认证绕过，故定 P1（计划字面 P0 供裁量）
- 建议修复：启动时显式 uvicorn.run(proxy_headers=False) 或 trusted_hosts=[]；或应用层剥离 XFF 后再判回环
**P1-8｜[D8] XFF 伪造来源头可打穿限流：桶枯竭时带 X-Forwarded-For: 203.0.113.9 请求返回 200（plain 429 / xff 200）**
- 位置：uvicorn ProxyHeadersMiddleware（proxy_headers 默认开，trusted_hosts=127.0.0.1）→ app/middleware/rate_limit.py 按 scope['client'] 计键
- 根因初判：回环对端的 XFF 被 uvicorn 信任并改写 scope['client']，限流键随之切换为伪造 IP（全新满桶）；与 D2 的同源行为一致（XFF 同时影响回环判定与限流键），但均破坏『仅信任真实 TCP 来源』设计语义。非回环对端不在 trusted_hosts，XFF 被忽略，故仅为本地纵深缺陷，无远端可利用面（服务只绑 127.0.0.1）
- 建议修复：启动时 uvicorn.run(proxy_headers=False) 或显式 forwarded_allow_ips=[]；保证 scope['client'] 恒为真实 TCP 对端，使限流键与回环判定均不可被头部操纵

## 4. 关键结论与口径修正（对计划的反馈）

1. **scan/text 实际按 P3-9 去重**（text_hash 全等 + SimHash/二元组近重复复用 detection 行），计划『scan 每次调用都生成新检测（非去重）』的假设与实现不符——E1/E2 中 25 条**内容充分不同**的扫描文本才产生 25 条新检测；同文本二次扫描返回同一 detection_id 属设计行为（防库膨胀），非缺陷（B9③、E2 口径按实现修正）。
2. **zhihu/import 近重复去重**：同一骗术短语不同长度的文本（如 10 万字与 20 万字同短语）会被 `find_near_duplicate`（overlap≥0.85）判为重复 → ingested=0（B2 首次执行即如此）。测试需用内容相异的载荷，产品行为符合 P3-9 设计。
3. **D2/D3 回环矩阵的来源语义**：计划 403 预期隐含『非回环来源』。本机回环来源下 local-login/current-key/reset-key 合法放行（本机一键登录设计）；X-Real-IP/X-Client-IP/Forwarded 从未参与来源判定。关键发现：**uvicorn proxy_headers 默认信任回环对端的 XFF** → 回环来源 + XFF=127.0.0.1 → 200（计划 D2⑤ 字面 P0），且**限流键随之被 XFF 操纵**（D8：桶枯竭后带 XFF 即换新桶 → 200）。非回环对端不在 trusted_hosts，XFF 被忽略（已核对 uvicorn 源码）→ 无远端可利用面（服务仅绑 127.0.0.1）。
4. **stats.generated_at 为 UTC**（本地 UTC+8 差 8 小时）：`datetime.now(timezone.utc)` 生成，与日志本地时间不一致（E2 观察项，建议统一时区口径）。
5. **reset-key 实际执行多次**：C9 前通知团队后轮换；D3 重测时因回环来源 + X-Real-IP 头（来源合法）再次真实轮换。**当前 admin key 以 `data/bootstrap_admin_key.txt` 为准**（`af_admin_6fea238a`），所有旧 key（239aa3c0/5b65b932/b1b9f60c/9487c750/7c381269/26e76ba1/a2ca487b 等）已全部失效（C9 8×2 矩阵验证 401 零例外）。
6. **限流实测**：默认 60/min 令牌桶按真实 TCP 来源计（含回环来源 XFF 重写影响，见 D8）；第 62 次起 429（期间桶以 1/s 补发）；admin key 豁免有效；65s 后自动恢复。
7. **MCP 错误透传**：REST 4xx 经 mcp SDK 2.x 包装为 `isError` 结果，但具体错误码/消息对客户端不可见（仅 'Error executing tool <name>'）——非吞错成 200，但违反『错误码原样透传』铁律（A8）。
