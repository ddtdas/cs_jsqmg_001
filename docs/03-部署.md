# 03 · 部署

> 适用：Windows（本项目主环境）与 Linux/macOS。项目根 `<ROOT>` = `C:\Users\Administrator\Desktop\知乎黑客松\金丝雀蜜罐`

## 1. 一键启动（Windows）

`start.bat` 已内置真实路径：

```bat
@echo off
set PROJECT_ROOT=C:\Users\Administrator\Desktop\知乎黑客松\金丝雀蜜罐
set PORT=9200
call "%PROJECT_ROOT%\.venv\Scripts\activate.bat"
python -m app.run --host 127.0.0.1 --port %PORT%
```

双击或命令行执行 `start.bat` 即可。首次运行前确保 `.venv` 已创建并安装依赖（见 [01-快速开始](01-快速开始.md)）。

> 单实例互斥（R1 P1-5 / R3 P3-5）：脚本按 9200 监听 PID 检测已运行实例，清理命令行含
> `app.run --port 9200` 但非监听 PID/非监听父进程的僵尸实例（保护 venv 重定向父进程）；
> R3 起匹配精确为 `--port 9200`，且启动后等待 ~2s 复核端口归属、收敛同秒双启动为单实例；
> CIM 不可用时跳过清理、绝不阻塞启动。

## 3. 配置项（.env）

复制 `.env.example` 为 `.env` 后按需修改（全部以 `AF_` 前缀注入，也可直接设环境变量）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `AF_HOST` / `AF_PORT` | `127.0.0.1` / `9200` | 监听地址/端口 |
| `AF_DATA_DIR` | `data` | 数据目录（db/key 存放处） |
| `AF_API_KEY` | 空 | 显式 admin key（空则自动生成文件） |
| `AF_LLM_BASE_URL` / `AF_LLM_API_KEY` / `AF_LLM_MODEL` | 空 | LLM 路由（三者齐备才启用；否则降级纯规则） |
| `AF_LLM_TIMEOUT` / `AF_LLM_DAILY_BUDGET` | `30` / `0` | 超时 / 每日预算（0=不限） |
| `AF_ZHIHU_RATE_LIMIT` | `20` | 知乎全局令牌桶（请求/分钟） |
| `AF_ZHIHU_ENCRYPT_KEY` | 空 | cookie 加密密钥（空则自动生成 `data/secret.key`） |
| `AF_ZHIHU_KEY_FILE` | 空 | Fernet 密钥独立文件路径（P3-8；优先于 `data/secret.key`，建议放数据目录外） |
| `AF_RATE_LIMIT_PER_MIN` | `60` | 公开热路径按 IP 令牌桶配额（0=关闭） |

## 4. 数据与密钥

| 文件 | 作用 | 注意 |
|---|---|---|
| `data/af.db` | SQLite 主库（WAL） | 首次启动自动建表+种子；勿手工编辑 |
| `data/bootstrap_admin_key.txt` | admin key（`af_admin_*`） | **勿提交仓库**（已在 .gitignore） |
| `data/secret.key` | cookie Fernet 加密密钥 | 丢失后历史 cookie 无法解密 |
| `webui/dist/` | WebUI 构建产物 | 主控在 `/ui/` 静态托管（目录存在时自动挂载） |

> 密钥文件权限（P3-8）：Linux/macOS `chmod 600`；Windows 建议目录 ACL 限制为当前用户
> （`icacls <key文件> /inheritance:r /grant:r "%USERNAME%:R"`）。
> 建议通过 `AF_ZHIHU_KEY_FILE` 把密钥放到 `data/` 之外（如 `var/secrets/zhihu.key`），
> 避免密钥与密文同目录、数据目录整体泄露时 Fernet 形同虚设。

## 5. 生产部署建议

- 仅本机/受控内网使用：保持 `127.0.0.1` 绑定，不暴露公网。
- 若需公网访问 WebUI，前置反向代理（如 Nginx）+ HTTPS，并在代理层做访问控制。
- 定时备份 `data/` 目录（db + 密钥分开备份）。
- 升级流程：`pip install -r requirements.txt`（新依赖）→ 重启主控（`ensure_schema` 幂等自动迁移）。

### 5.1 存量数据去重清洗（R2 新增运维工具）

`scripts/cleanup_duplicates.py`（幂等；建议先 `--dry-run` 预演再真删；执行前自动备份到 `var/backups/` 并写审计）：

```bash
.venv\Scripts\python.exe -m scripts.cleanup_duplicates --dry-run   # 预演（不删除）
.venv\Scripts\python.exe -m scripts.cleanup_duplicates             # 实际清洗
```

- 清洗范围：cases 同 det 重复（保留最早一条，其余删除）；evidence_packages 完全冗余**未冻结**包。
- **已冻结证据包永不自动删除**（法律存证语义）；脏 det_ids（非 JSON）行跳过不中断（json_valid 门控）。
- 审计：events(kind='data_cleanup') + gate_logs(action='data.cleanup_duplicates') 哈希链。
- R2 线上已执行：cases 1695→80（删 1615）、evidence_packages 738→103（删 635，冻结 86 全部保留）。
