### 1.2 P2-1：`_escalate_pending` 重放后终态收敛（scheduler.py）

- 问题（t9 P2-1）：`_escalate_pending` 重放成功后不删除/不标记 pending 事件行 → events 无界增长、
  每轮 job 全量重扫；检测已删除时每轮 detection_not_found 重试永不收敛。
- 修复（scheduler.py `_escalate_pending` 重写）：
  - 查询只取未终态行：`json_valid(payload)=1 AND json_extract(payload,'$.resolved') IS NULL
    AND json_extract(payload,'$.terminal') IS NULL`；
  - 升级成功或检测已升级（幂等跳过）→ payload 追加 `resolved=true + recovered + resolved_at`
    （升级成功留 recovered 审计事件，pending 行保留为审计记录但不再重扫）；
  - 检测不存在（已删除）→ payload 追加 `terminal=true + reason='detection_deleted' + resolved_at`
    （终态，停止重试）；
  - 仅瞬时异常（DB busy 等）保持原状留待下轮；
  - 返回 `(done, terminal)` 元组，job 日志记录两者。
- 验证：tests/test_r8_r3fixes.py::test_pending_marked_resolved_after_replay（重放后 pending 行
  resolved=true，第二轮零新增升级）、test_pending_terminal_on_deleted_det（不存在检测 → terminal
  终态，第二轮不报错不重试）。
