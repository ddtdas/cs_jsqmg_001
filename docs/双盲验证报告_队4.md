## 三、发现清单（P0/P1/P2）

- **P0（阻断）**：无。主控全程可用，无数据破坏/越权/绕过。
- **P1（重要功能缺口）**：
  1. **典型高发诈骗话术漏检**：中奖类（S4）与钓鱼链接+验证码类（S5）0 命中判 normal（域2/13）。当前规则库覆盖投资/刷单/冒充公检法/冒充客服等，但对"中奖+手续费"与"索要卡号验证码"类无 pattern；LLM 未配置时无兜底 → 直接漏报风险。
  2. **SE 分析（攻击向量+心理技巧）从未产出**：`scan/text.se_analysis` 恒 null、`detections/{id}/full.se_factors` 不存在于任何检测（含 LLM 时代检测）→ 域 2/11 中"se_analysis 字段存在（攻击向量+心理技巧）"的验收语义未达成（字段占位存在、内容未落地）。
- **P2（次要/规范性）**：
  3. **成功写操作返回 4xx**：`traps/deploy`=400、`traps/check-hit`(命中)=409、`evidence/freeze`=409，body 均为 `ok:true` 且状态变更生效 —— HTTP 状态码与语义不符（影响客户端契约）。
  4. **`PUT /config` 缺 confirm 返回 422 而非 403**（confirm=false 才 403）：行为安全达成，但与验收描述状态码不一致。
  5. **混合鉴权公开写入口**：`/scan/text`、`/accounts/check` POST 与 `/config`、`/scan/hits` GET 无 key 可访问（本机模式 `no_key_mode:true` 的设计取舍，但 accounts/scan 会产生写记录）。
  6. **ingest 检测不自动分级**：账号桥私信产生的检测 `status=pending、grade=null`（与 scan/text 即时分级行为不一致）。
  7. 部分端点对错误输入的语义化处理良好（seed_required / not_configured / confirm_required / sensitive_data / reason_too_short），校验消息可读性强 —— 正面观察。

## 四、与功能域的交叉点标注

- **域2 ↔ 域3**：scan 结果直接驱动分级，`grade_hint` 与最终 `grade` 联动（S1 因 9<10 分 L3→L2）；`grade_reason` 与 `explain` 完全一致。
- **域2 ↔ 域7**：L3 及以上自动生成告警（本批 S2/S3 触发 alert 1466/1467，channel=webui）。
- **域3 ↔ 域11**：`explain` 与 `detections/{id}/full.grade_reason` 证据链同源。
- **域4 ↔ 域3/域7**：蜜饵命中 → `trap_retired` 事件 + retired 状态；**未生成 L5 detection**（L5 描述含"蜜饵实锤命中"，但当前实现路径为蜜饵状态机 retired，而非检测升级 L5；LLM 路径的 L4/L5 需 LLM 配置后可达）。
- **域10 ↔ 域5**：zhihu/ingest 返回体内嵌 `account_intel`（复用 accounts/check 判定）。
- **域10 ↔ 域7**：ingest 产生 `dm_received` 事件（含 from/dm_id）。
- **域6 ↔ 域2**：evidence 打包的 speech_hits 与 scan 命中逐条一致；case 发布 `graph_tags` 取自命中分类（impersonation）。
- **域12 ↔ 域3**：供应链反查节点带 risk 分层（L1/L2/L6），与分级体系 L1-L5 概念分域（供应链为 L1-L7 分层标注）。
