# 04 · 知乎通道（ZhihuBridge）

> 现实约束（主方案 §5.1）：知乎开放平台**不向个人开发者开放** OAuth，因此不存在"官方 API 直连"。
> 本项目通过**多通道适配器**读取自有账号数据（私信/评论/公开资料）与公开聚合信息，且遵守平台反爬与合规边界。

## 1. 四通道

| 通道 | 方式 | 状态 | 说明 |
|---|---|---|---|
| **CH-A** | Playwright 浏览器会话（主通道） | 依赖 playwright（可选依赖，缺失自动降级） | 读自有私信/评论/关注流；headless 可配 |
| **CH-B** | httpx 私有 API 模拟（备用） | 遇 x-zse-96 等签名校验标记 degraded | 仅低敏读操作；失败自动切 CH-A |
| **CH-C** | RSSHub 只读公开聚合 | `AF_ZHIHU_RSSHUB_BASE`（默认 rsshub.app） | 热榜/问题/用户动态，零登录 |
| **CH-D** | 手动导入（保底） | ✅ 已落地 | 粘贴文本/JSON 文件 → 同一检测流水线；演示与离线必用 |

## 2. 手动导入（CH-D，当前最常用）

```bash
curl -X POST http://127.0.0.1:9200/api/v1/zhihu/import \
  -H "Content-Type: application/json" \
  -d '{"content":"收到一条私信：<对话文本或JSON数组>"}'
```

- 纯文本 → 一条检测；JSON 消息数组 → 逐条拆分检测；按文本哈希去重；空内容拒绝。
- 导入后进入话术识别流水线（R2），可查 `/scan/hits`。

## 3. cookie 注入（CH-A/CH-B 前置）

```bash
curl -X POST http://127.0.0.1:9200/api/v1/zhihu/channels/ch_a/login \
  -H "X-API-Key: af_admin_xxxxxxxx" -H "Content-Type: application/json" \
  -d '{"cookie":"<用户自行从浏览器导出的 cookie>"}'
```

- **cookie 由用户手动导出粘贴**（HITL 精神一致），系统以 Fernet 加密存储于 `zhihu_sessions`（`data/secret.key`），**明文不回显**。
- 注入后调用 `POST /zhihu/channels/{id}/verify` 验证；垃圾/非 cookie 内容会被拒绝（测试覆盖）。

## 4. 频率控制与退避

- 全局令牌桶：`AF_ZHIHU_RATE_LIMIT`（默认 20 请求/分钟），超限 429。
- 失败指数退避：连续失败触发 cooldown，冷却后自动恢复（`/zhihu/status` 可查）。
- 长任务交给调度器，避免高频轮询。

## 5. 合规边界

- **只读自有/公开数据**：私信/评论/公开资料；**不扫**手机号/定位/关注图谱外数据。
- 访问频率受令牌桶限制，遵守平台反爬政策与服务条款。
- cookie 仅用于自有账号会话读取，不用于批量爬取、不共享、不转发。
- 违反《个保法》的采集（如未授权个人信息批量收集）一律禁止。

> 详细接口签名与降级逻辑见 `app/services/zhihu_bridge.py`；测试见 `tests/test_p2_zhihu.py`。
