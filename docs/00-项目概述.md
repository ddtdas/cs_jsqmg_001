# 00 · 项目概述

> 金丝雀蜜罐 CanaryGuard AntiFraud v1.0.0 —— 社区成员**第一人称反诈工具**。

## 1. 定位

把"识别诈骗→留证→举报"这件事，降维成普通人可执行、可验证的五个环节（**五环降维**）：

```
蜜饵诱捕（R1）→ 话术识别（R2）→ 账号速查（R3）→ 五级分级（R4）→ 证据案例（R5/R6）
```

系统只做**侦查取证与分级提醒**：产出蜜饵草稿、话术判定、账号风险、证据包、举报模板；
**不**自动发布、**不**自动钓鱼、**不**冻结拦截、**不**冒充官方。

## 2. 双形态

| 形态 | 入口 | 说明 |
|---|---|---|
| 独立软件 | WebUI `http://127.0.0.1:9200/ui/` | FastAPI 主控 + Vue3 管理台 + 知乎通道 + SQLite |
| MCP Server | stdio / `--http --port 9201` | 55 个 `af_*` 工具，供 dsh / Claude Code / Codex 调用 |

**同一内核（D1）**：所有业务逻辑在 FastAPI 主控；WebUI 与 MCP 都是 REST API 客户端，
MCP 是纯透传代理——两种形态能力一致，无第二套逻辑。

## 4. 功能主线 R1–R6

| # | 主线 | 一句话 | 关键保障 |
|---|---|---|---|
| R1 | 蜜饵诱捕 | 生成带指纹的诱饵话术草稿，用户手动部署后监控踩饵 | 只产草稿不发布（HITL）；命中即退役防反查并联动检测升级 L5（job 与手工 check-hit 均联动，trap_hit_escalated 事件；R1/R2 修复）；改写 5-10 字仍召回 |
| R2 | 话术识别 | 输入文本 → 规则/LLM 双确认 → 命中与证据 token | 已知话术 100% 命中，正常语料 0 误报（测试固化） |
| R3 | 账号速查 | 公开信号评分 → 绿/黄/红 + 证据链 + 共现团伙提示 | 只用公开信号，私有信号白名单丢弃 |
| R4 | 五级分级 | L1–L5 信号融合，输出可解释证据链；L3+ 才告警；L3+ 自动触发社工库核查（R1 修复） | ≤L3 不产生正式报告（闸控） |
| R5 | 证据包 | 截图/哈希链/时间戳 → 冻结 → 导出 + 举报模板；同一检测重复建包 409 evidence_exists（R1 修复） | 冻结后不可篡改；模板分 96110/平台/辟谣三类 |
| R6 | 案例库 | 双层脱敏 → 脱敏案例入库 → 查询 + 骗术图谱；同一检测仅一个案例（应用层同载荷幂等/异载荷 409 case_exists + **DB 层 UNIQUE(det_id) 索引双保险，R1/R3 修复**） | 含敏感信息拒绝入库（测试固化） |
| P19 | 反钓鱼伪装 | 伪装身份档案（parent/layer 嵌套 + 假信息字段）→ 主动暴露（HITL，返回脱敏清单供回复骗子"泄露"）→ 骗子接触登记（脱敏落库 + IOC 掩码 + 同号二次锁定 escalated）→ 伪装地图 | 假信息仅用于防御验证；真实号码脱敏 + IOC 掩码明文不落库；全部端点 require_admin（D6），toggle/delete confirm+reason 审计 |

## 5. 设计原则

- **D1 双形态同一内核**：无第二套逻辑。
- **D2 确定性优先**：蜜饵踩饵命中 = 实锤（非概率）。
- **D3 HITL 铁律**：永不自动发布、永不自动钓鱼。
- **D4 LLM 当敌对输入**：fence + schema 校验 + 数值钳制。
- **D5 降级链完整**：LLM 不可用 → 规则，系统不瘫。
- **D6 认证与审计**：bootstrap admin key + 敏感操作 confirm+reason。
- **D7 合规红线**：只读公开/自有信息；脱敏强制；处置权归官方。

## 6. 合规红线（摘要）

详见根 `README.md`「⚠️ 合规声明」。核心：

1. **非官方工具**，与知乎官方无合作、不冒充官方；
2. **只侦查取证，不处置执法**——冻结/拦截/点名/举报受理一律归官方（96110/国家反诈中心 APP/知乎平台）；
3. **HITL**：一切对外动作由用户手动完成；
4. **数据最小化**：cookie 加密存储、案例强制脱敏、遵守知乎服务条款与《个保法》。
