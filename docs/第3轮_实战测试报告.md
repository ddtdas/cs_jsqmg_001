## 3. 问题清单（分级）

### P0

无

### P1

**P1-1｜[U1] UI 案例发布功能不可用：发布弹窗无 confirm 复选框与 reason 字段，webui 端 publishCase(detId, redacted, tags) 未传 confirm/reason → 后端恒 403 confirm_required**
- 位置：webui/src/views/CasesView.vue:86 + api/client.js:179
- 根因初判：前端未暴露敏感操作双确认控件；后端 PublishCaseRequest 强制 confirm+reason
- 建议修复：发布弹窗补 confirm 复选框 + reason 输入（≥20 字），提交时传 confirm:true+reason；与第1轮 A5/API 行为对齐
**P1-2｜[X1] LLM 熔断后无自动恢复：mock 恢复后 llm_used 仍 false，需重启进程才能复用 LLM**
- 位置：app/services/llm_provider.py（degraded 单例 + 无半开探测）
- 根因初判：熔断状态持久（if self.degraded: raise），无时间窗半开/定时重试/reset 端点
- 建议修复：熔断加时间窗半开探测（如 60s 后放行一次探活）或提供 POST /ops/llm-reset；或文档明确『需重启』

### P2

**P2-1｜[X1] LLM 熔断无日志记录（仅内存 hook llm_degraded，运维无法从日志感知熔断状态）**
- 位置：app/services/llm_provider.py _degrade ｜ 根因：降级只发 hook 不写日志 ｜ 建议：降级/恢复时写 INFO/WARN 日志

## 4. 关键结论

1. **并发写隔离在第 2 轮修复后在大规模下成立（C4/C5/C7/C8）**：30 并发 publish 全 200、10 分钟跑批 10449 请求零 5xx/零 404/零 429、同蜜饵 10 并发 check-hit hit_count=1 事件=1、10 并发 freeze 恰 1×200+9×409、20 并发 build verify 全 intact——第 2 轮 P1-D4 修复无复发。
2. **U1 真实用户 11 步流程 10/11 通过**：唯一失败为⑧ UI 案例发布（webui 弹窗缺 confirm/reason → 恒 403），已记 P1 交 webui-dev。
3. **X1 LLM 熔断降级不瘫（纯规则 200）但无自动恢复（预期 P1）**：mock 恢复后 llm_used 仍 false，需重启进程；另熔断无日志（P2）。
4. **故障恢复全部通过**：X5 写锁期间 503 db_busy（5.1s）→ 释放后 200、只读期间写 500 恢复 200、integrity ok；X6 强杀后 5 条 pending 零丢失、integrity ok、key 未轮换（D3 重启不换 key 成立）；X7 3 轮 stop/start 端口释放+health 200+PID 变化；X8 调度器注入异常不崩、6 job 保留。
5. **X4 知乎限流单例生效**：AF_ZHIHU_RATE_LIMIT=3 下 25 次 gate = 3 过 22 拒，指数退避 cap 60s，70s 冷却后恢复。
6. **35 分钟长稳（L1）**：RSS 稳定约 72MB（波动<20%）、WAL 峰值 4.2MB（checkpoint 生效）、health 全程 200、日志平稳无刷屏。
7. **规模（S/C5 叠加）**：detections 3000+/traps 1300+/cases 1600+/alerts 1000+ 下分页无重复、过滤自洽；7 端点 p95 均 <50ms（大库无退化）；timeline 316ms。
8. **执行口径**：C5 跑批脚本主循环快照子进程挂起被终止，指标改由 app.log 全文件（含轮转）重算；2×422 系发布载荷偶发脱敏拒绝（<0.2% 守卫口径）；X4/部分用例首测失败为测试脚本解析/等待缺陷，修正后数据自始正确。
