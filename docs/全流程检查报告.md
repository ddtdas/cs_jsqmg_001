## 2. 主动防御 —— 断（P0：自动触发缺失）

> ⚠️ R2 复核注：本章描述为 2026-09-16 检查时快照；该 P0 已由严格验收 R1 修复（grading.py `_auto_soc_analysis`，test_r6_r1fixes.py::test_job_trap_recheck_awaits_hit_and_escalates_l5 等 5 条回归全绿），当前 L3/L4/L5 分级后自动触发社工库分析。原文保留作历史对照。

**核心问题（任务重点）**：`grading.py` **没有**调用 `SocLibService().analyze`。
- `services/grading.py` 全文：只做 rule+LLM 信号融合、grade/grade_reason 落库、AlertService.evaluate，**无 soc_lib 引用**
- 全仓 grep `SocLibService|soc_lib|analyze`：`SocLibService().analyze` 唯一调用点 = `api/soc_lib.py::soc_lib_analyze`（POST /soc-lib/analyze/{det_id}，require_admin，手动触发）
- `speech_engine.py`（analyze_detection / scan_text）、`scheduler.py` 8 个 job、`alerting.py` 均无 soc_lib 调用
- 前端 DetailDrawer 社工库卡：被动数据源 `detection.se_factors.soc_analysis`（服务层从未写该字段 → 恒空）+ 主动「触发主动防御」按钮（调 `api.socLibAnalyze` → 手动触发）→ **卡有，但无自动数据**

**实测证据**：
1. `GET /soc-lib/status` → `{"hibp_configured":false,"local_records":3}`（本地库 3 条演示种子就绪；HIBP 未配）
2. 手动 `POST /soc-lib/analyze/3122` → `{"analyzed":3,"hits":[{phones 13*******00 found:true,local},{qq found:true},{wechat found:false}]}` → events 落库 `soc_lib_hit` 16861/16862（det_id 3122，掩码 IOC，明文不落库 ✅）
3. 事件流历史 total=4：仅两次手动触发（3115 于 20:21:13、3122 于 20:43:12）——**无任何自动产生的 soc_lib_hit**

**断点**：需求「grading L3+ → SocLibService.analyze」未落地；L3+ 分级完成 ≠ 自动发起社工库分析。前端社工库卡只能靠人工点按钮，且被动数据源字段永不填充。

**建议（P0）**：
- 在 `GradingService.finalize`（或 `job_scan_dm` 内、或新增 `job_soc_lib` 定时）对 grade ∈ {L3,L4,L5} 的检测自动调用 `SocLibService().analyze(det_id, extract_iocs(content), conn)`，命中写 soc_lib_hit（服务层已是幂等降级设计，接入成本低）
